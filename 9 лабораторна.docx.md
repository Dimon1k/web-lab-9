# **Опис**

У цій лабораторній роботі потрібно створити простий Angular-застосунок для навчального проєкту «Акустична варта». За принципом він схожий на Todo list: користувач бачить список елементів і може додавати, змінювати та видаляти їх. У нашому випадку елементами списку будуть датчики міського шуму.

Backend і база даних у цій роботі не потрібні. Дані зберігаються тільки в пам’яті Angular-застосунку і після перезавантаження сторінки повертаються до початкового списку.

**Примітка.** Методичні вказівки орієнтовані на Angular 22, актуальну стабільну гілку станом на 02.11.2026. Новий проєкт створюємо як standalone-застосунок без AppModule, SSR і SSG.

# **Мета роботи**

Навчитися створювати простий Angular-застосунок, працювати з компонентом і шаблоном, відображати список даних, обробляти натискання кнопок, виконувати production build та публікувати готовий застосунок через GitHub Pages.

1\. Встановити Node.js, npm та Angular CLI.

2\. Створити Angular-проєкт acoustic-watch.

3\. Запустити проєкт локально через ng serve.

4\. Описати модель Sensor та створити початковий список датчиків.

5\. Відобразити датчики за допомогою @for.

7\. Виконати ng build і перевірити файли в dist.

8\. Опублікувати застосунок на GitHub Pages.

# **1\. Що потрібно створити**

На сторінці має бути форма додавання датчика та список карток. Кожна картка показує назву датчика, район, рівень шуму і статус.

• перегляд списку датчиків;

• додавання нового датчика;

• видалення датчика;

• перемикання статусу active / inactive;

• просте візуальне оформлення active та inactive.

Для цієї роботи достатньо одного основного компонента. Сервіси, маршрутизація, RxJS, NgRx, Angular Material та backend **не використовуємо.**

Перейдіть у папку, де зберігаєте навчальні проєкти, і виконайте:

• SSR / SSG \- No;

• AI configuration \- None, якщо таке питання з’явиться;

• standalone \- залишити стандартний варіант;

• інші необов’язкові параметри \- залишити значення за замовчуванням.

# **6\. Створення моделі датчика**

У папці src/app створіть файл sensor.ts:

export interface Sensor {  
  id: number;  
  name: string;  
  district: string;  
  noiseLevel: number;  
  status: 'active' \| 'inactive';  
}

| Поле | Значення |
| :---- | :---- |
| id | Унікальний номер датчика. |
| name | Назва датчика. |
| district | Район міста. |
| noiseLevel | Рівень шуму в децибелах. |
| status | Стан датчика: active або inactive. |

Interface описує форму об’єкта. TypeScript перевіряє, щоб кожен Sensor мав усі ці поля з правильними типами.

# **7\. Логіка компонента: app.ts**

Відкрийте src/app/app.ts і замініть його вміст таким кодом:

import { Component } from '@angular/core';  
import { FormsModule } from '@angular/forms';  
import { Sensor } from './sensor';

@Component({  
  selector: 'app-root',  
  standalone: true,  
  imports: \[FormsModule\],  
  templateUrl: './app.html',  
  styleUrl: './app.css'  
})  
export class App {  
  sensors: Sensor\[\] \= \[  
    {  
      id: 1,  
      name: 'Сенсор Центр',  
      district: 'Галицький',  
      noiseLevel: 72,  
      status: 'active'  
    },  
    {  
      id: 2,  
      name: 'Сенсор Сихів',  
      district: 'Сихівський',  
      noiseLevel: 58,  
      status: 'active'  
    },  
    {  
      id: 3,  
      name: 'Сенсор Левандівка',  
      district: 'Залізничний',  
      noiseLevel: 45,  
      status: 'inactive'  
    }  
  \];

  newName \= '';  
  newDistrict \= '';  
  newNoiseLevel: number \| null \= null;

  addSensor() {  
    const name \= this.newName.trim();  
    const district \= this.newDistrict.trim();

    if (\!name \|\| \!district \|\| this.newNoiseLevel \=== null) {  
      return;  
    }

    const nextId \= this.sensors.length  
      ? Math.max(...this.sensors.map(sensor \=\> sensor.id)) \+ 1  
      : 1;

    this.sensors.push({  
      id: nextId,  
      name,  
      district,  
      noiseLevel: this.newNoiseLevel,  
      status: 'active'  
    });

    this.newName \= '';  
    this.newDistrict \= '';  
    this.newNoiseLevel \= null;  
  }

  deleteSensor(id: number) {  
    this.sensors \= this.sensors.filter(sensor \=\> sensor.id \!== id);  
  }

  toggleStatus(id: number) {  
    const sensor \= this.sensors.find(sensor \=\> sensor.id \=== id);

    if (sensor) {  
      sensor.status \= sensor.status \=== 'active' ? 'inactive' : 'active';  
    }  
  }  
}

## **Що важливо в цьому коді**

• FormsModule потрібен для \[(ngModel)\] у полях форми.

• sensors \- масив з початковими датчиками.

• newName, newDistrict і newNoiseLevel \- значення, які вводить користувач.

• addSensor() додає новий об’єкт Sensor до масиву.

• deleteSensor() залишає в масиві всі датчики, крім вибраного.

• toggleStatus() перемикає active на inactive і навпаки.

# **8\. HTML-шаблон: app.html**

Відкрийте src/app/app.html і замініть початковий шаблон:

\<main class="container"\>  
  \<h1\>Акустична варта\</h1\>  
  \<p class="subtitle"\>Список датчиків міського шуму\</p\>

  \<section class="sensor-form"\>  
    \<h2\>Додати датчик\</h2\>

    \<input  
      type="text"  
      placeholder="Назва датчика"  
      \[(ngModel)\]="newName"  
    /\>

    \<input  
      type="text"  
      placeholder="Район"  
      \[(ngModel)\]="newDistrict"  
    /\>

    \<input  
      type="number"  
      placeholder="Рівень шуму, дБ"  
      \[(ngModel)\]="newNoiseLevel"  
    /\>

    \<button type="button" (click)="addSensor()"\>  
      Додати датчик  
    \</button\>  
  \</section\>

  \<section class="sensor-list"\>  
    @for (sensor of sensors; track sensor.id) {  
      \<article  
        class="sensor-card"  
        \[class.inactive\]="sensor.status \=== 'inactive'"  
      \>  
        \<h3\>{{ sensor.name }}\</h3\>  
        \<p\>Район: {{ sensor.district }}\</p\>  
        \<p\>Рівень шуму: {{ sensor.noiseLevel }} дБ\</p\>  
        \<p\>Статус: \<strong\>{{ sensor.status }}\</strong\>\</p\>

        \<div class="actions"\>  
          \<button type="button" (click)="toggleStatus(sensor.id)"\>  
            Змінити статус  
          \</button\>  
          \<button  
            type="button"  
            class="delete-button"  
            (click)="deleteSensor(sensor.id)"  
          \>  
            Видалити  
          \</button\>  
        \</div\>  
      \</article\>  
    } @empty {  
      \<p\>Датчиків поки немає.\</p\>  
    }  
  \</section\>  
\</main\>

## **Коротке пояснення Angular-синтаксису**

| Синтаксис | Що означає |
| :---- | :---- |
| @for (sensor of sensors; ...) | Повторює HTML-блок для кожного датчика з масиву sensors. |
| sensor of sensors | sensor \- поточний елемент; sensors \- масив. |
| track sensor.id | Angular використовує id, щоб відстежувати конкретну картку у списку. |
| {{ sensor.name }} | Підставляє значення з TypeScript у HTML. |
| (click)="..." | Викликає метод після натискання кнопки. |
| \[(ngModel)\]="..." | Зв’язує поле вводу зі змінною у компоненті. |
| \[class.inactive\]="..." | Додає CSS-клас inactive, коли умова істинна. |

# **13\. Перевірка файлів з dist**

У звіті потрібно показати файл index.html із папки dist. Не потрібно доводити роботу production-версії подвійним натисканням на index.html. Відкриття через file:// не є правильним способом перевірки Angular-збірки.

Запустіть простий локальний HTTP-сервер у корені Angular-проєкту:

| npx http-server dist/acoustic-watch/browser |
| :---- |

Під час першого запуску npx може запропонувати тимчасово встановити пакет http-server. Підтвердьте встановлення. Потім відкрийте адресу, яку покаже команда, наприклад http\://127.0.0.1:8080.

До звіту додайте:

1\. скріншот папки dist/acoustic-watch/browser;

2\. скріншот файлу dist/acoustic-watch/browser/index.html у провіднику або редакторі;

3\. скріншот production-версії, відкритої через локальний HTTP-сервер.

Коротко: ng serve запускає застосунок для розробки, а ng build створює готові файли для публікації. Папка dist з’являється саме після збірки.
